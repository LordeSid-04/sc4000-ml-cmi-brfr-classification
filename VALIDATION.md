# Preprocessing validation update

Checked on 15 October 2026.

## Changes

- The default pipeline no longer applies mirror/sensor-permutation or upside-down settings selected using gesture labels from the full dataset. The original correction functions remain opt-in for exploratory work. Establish them independently or fit them on training subjects only before claiming held-out improvements.
- Feature tables, per-row arrays, canonical signals and all six scalers were rebuilt together using the revised defaults. Old cached arrays must not be mixed with this build.
- A missing subject match no longer falls back to another person's demographic row.
- The parity checker now fails when a real test example fails its shape/schema check.
- Recursive cleanup is restricted to the two generated build folders under this repository.
- The README corrects the whole-temperature dropout count to 96 and replaces the unavailable Release link with explicit rebuild instructions. It also distinguishes local ZIP creation from publishing a release.

## Scores

`scripts/04_validate_trees.py` records five-fold reference scores in `data/processed/validation.json`.
It rejects metadata that enables the globally label-tuned corrections, checks subject separation and
label/feature alignment, and trains on full-sensor plus IMU-only versions of training recordings only.

These are grouped-CV reference results for fixed features and model settings. They are not a new
untouched test-set estimate, a nested tuning estimate or proof of every feature's individual benefit.
The earlier globally calibrated scores and ablation gains remain historical exploratory results.

Completed reference run (LightGBM 4.7.0, 500 estimators, seed 42):

| Inputs | Mean fold score | Fold standard deviation | Pooled out-of-fold score |
|---|---:|---:|---:|
| All sensors | 0.796366 | 0.008134 | 0.796271 |
| Motion only | 0.730243 | 0.013783 | 0.730496 |

The validation command was also checked against metadata enabling a globally tuned correction;
it refused the unsafe configuration before training. These reference results do not establish that
the optional orientation transformations are physically wrong; they remove that full-data selection
from this evaluation.
